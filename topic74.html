DTD (Document Type Definition)

1. Introduction

DTD stands for Document Type Definition. It is used to define the structure and rules of an XML document.

DTD tells us which elements and attributes are allowed in an XML document and how they should be arranged.

2. Purpose of DTD

  • It defines the structure of XML documents.
  • It declares the elements used in XML.
  • It defines attributes of elements.
  • It specifies the order of child elements.
  • It helps validate XML documents.

3. Features of DTD

  • DTD defines the legal building blocks of XML.
  • It describes allowed elements and attributes.
  • It defines content models.
  • It can be written inside an XML document.
  • It can also be stored in an external .dtd file.

4. Types of DTD

A. Internal DTD

Internal DTD is declared inside the XML document. It is written within the DOCTYPE declaration.

Example:

<!DOCTYPE student [
    <!ELEMENT student (name, age)>
    <!ELEMENT name (#PCDATA)>
    <!ELEMENT age (#PCDATA)>
]>

<student>
    <name>Rahul</name>
    <age>18</age>
</student>

B. External DTD

External DTD is stored in a separate file having the .dtd extension. The XML document connects to it using the DOCTYPE declaration.

5. DTD Syntax

Some important DTD declarations are:

<!ELEMENT element-name content-model>

ELEMENT declaration defines an element and its allowed content. 

<!ATTLIST element-name attribute-name type default>

ATTLIST declaration defines attributes for an element.

6. DTD Example: Catalog

Create an external file named catalog.dtd. It requires one or more product elements. Each product contains a name followed by a price and must have an id attribute.

catalog.dtd

<!ELEMENT catalog (product+)>
<!ELEMENT product (name, price)>
<!ATTLIST product id ID #REQUIRED>
<!ELEMENT name (#PCDATA)>
<!ELEMENT price (#PCDATA)>

7. Matching XML Document

Save the following XML document as catalog.xml. It connects to the external DTD using the SYSTEM keyword.

catalog.xml

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalog SYSTEM "catalog.dtd">

<catalog>
    <product id="p101">
        <name>Notebook</name>
        <price>45.50</price>
    </product>

    <product id="p102">
        <name>Pen set</name>
        <price>30.00</price>
    </product>
</catalog>

8. Explanation of the Example

  • catalog is the root element.
  • product+ means one or more product elements.
  • Each product contains name and price.
  • id is an attribute of product.
  • ID defines the attribute as an identifier.
  • #REQUIRED means the id attribute is compulsory.
  • #PCDATA means parsed character data or text content.

9. Advantages of DTD

  • It defines a clear XML document structure.
  • It helps check whether XML follows expected rules.
  • It can be reused by multiple XML documents.
  • It supports both internal and external declarations.

10. Limitations of DTD

  • DTD has limited data typing.
  • DTD syntax is not itself XML.
  • It is less expressive than XML Schema (XSD).

Conclusion

DTD is used to define the allowed structure of an XML document. It declares elements, attributes and content models. It can be internal or external and helps validate XML documents according to defined rules.
