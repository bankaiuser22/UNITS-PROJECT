TOPIC 6: AJAX AND ASYNCHRONOUS WEB APPLICATIONS

1. Introduction to AJAX

AJAX stands for Asynchronous JavaScript and XML. It is a web development technique used to send HTTP requests from JavaScript and update a part of a web page without loading a completely new page.

AJAX allows a web application to communicate with a server in the background. JavaScript receives the response and updates the required part of the web page.

The name AJAX comes from an earlier period when XML was commonly used as a response format. Today, JSON is commonly used, but AJAX can also work with text, HTML, XML and other resources.

Example:

Suppose you are using a website and click a button to load course information.

Instead of refreshing the entire page, JavaScript can request the course information from the server and display it in a particular section.

Uses of AJAX:

  • Searching products in an online store.
  • Refreshing messages.
  • Checking whether a username is available.
  • Submitting a form without reloading the page.
  • Loading new information from a server.
Remember:
AJAX = Asynchronous JavaScript and XML.
It updates parts of a web page using data received from a server without loading a new document.

2. Why is AJAX Used?

In traditional web applications, a new page may need to load whenever the user requests new information. This can cause unnecessary page reloads.

AJAX helps avoid unnecessary full-page reloads. It allows JavaScript to request only the required information and update a particular part of the page.

Advantages of AJAX:

  • Reduces unnecessary page reloads.
  • Can reduce unnecessary data transfer.
  • Makes web applications more interactive.
  • Allows background communication with a server.
  • Helps display updated information quickly.
  • Keeps the rest of the page in place while updating a section.

Example:

On a shopping website, when a user searches for a product, AJAX can request matching products and update only the search results section.

3. How AJAX Works

AJAX works through communication between the browser and a server. JavaScript sends a request, receives a response and updates the required part of the web page.

Request and Response Cycle:

  1. User Action: A user performs an action, such as clicking a button or searching for a product.
  2. Send Request: JavaScript sends an HTTP request to a server URL. This URL is often called an endpoint.
  3. Server Processing: The server receives the request and processes it.
  4. Server Response: The server returns a response containing a status and, when appropriate, data such as JSON or text.
  5. JavaScript Reads Response: JavaScript checks the response and reads its data.
  6. Update Web Page: JavaScript updates the required DOM elements with the received information.

4. HTTP Methods Used in AJAX

HTTP methods describe what action the browser wants the server to perform. Two commonly used methods in AJAX are GET and POST.

1. GET Method

The GET method is used to request or retrieve information from a server.

Example:

fetch("/api/courses", {
    method: "GET"
});

Here, JavaScript requests course information from the server.

2. POST Method

The POST method is commonly used to send data to a server, for example when submitting a form.

Example:

fetch("/api/students", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        name: "Rahul"
    })
});

Here, JavaScript sends student information to the server in JSON format.

Difference:
GET = Used to retrieve data.
POST = Commonly used to send data.

5. Understanding Asynchronous Operations

Asynchronous means that an operation can start and finish later without forcing the entire browser interface to wait.

Network requests can take time. JavaScript uses asynchronous browser APIs such as fetch() so that the page can remain interactive while the request is being processed.

What is Synchronous?

A synchronous operation makes the next step wait until the current operation finishes.

What is Asynchronous?

An asynchronous operation allows other work to continue while the operation is waiting to finish.

Difference:

SYNCHRONOUS:

Task 1 starts
     |
     v
Task 1 finishes
     |
     v
Task 2 starts
     |
     v
Task 2 finishes


ASYNCHRONOUS:

Task 1 starts
     |
     v
Task 1 waits for result

Other work can continue

     |
     v
Task 1 result arrives
     |
     v
JavaScript handles result

Example from Daily Life:

Imagine you order food online. After placing the order, you do not have to stand still and wait without doing anything. You can continue using your phone while the order is being prepared.

Similarly, an asynchronous request allows the browser to continue responding while network activity is in progress.

Important:
Asynchronous does not mean that every JavaScript instruction runs in parallel. It means that JavaScript can continue other work while waiting for an asynchronous operation.

6. What is a Promise?

A Promise is a JavaScript object that represents the eventual result of an asynchronous operation.

For example, when JavaScript sends a request to a server, the result may not be available immediately. A Promise represents the work that will finish later.

Three States of a Promise:

1. Pending

The operation is still in progress and its final result is not available yet.

2. Fulfilled

The operation has completed successfully and produced a result.

3. Rejected

The operation failed and produced an error.

Simple Diagram:

           PROMISE
              |
       ----------------
       |       |      |
       v       v      v
    PENDING FULFILLED REJECTED
              |        |
              v        v
           SUCCESS   FAILURE

Example:

const myPromise = new Promise((resolve, reject) => {

    let success = true;

    if (success) {

        resolve("Task completed");

    } else {

        reject("Task failed");

    }

});

myPromise.then((result) => {

    console.log(result);

}).catch((error) => {

    console.log(error);

});

Explanation:

  • new Promise() creates a Promise.
  • resolve() marks the Promise as fulfilled.
  • reject() marks the Promise as rejected.
  • then() handles a fulfilled result.
  • catch() handles a rejected result.

7. What is Fetch API?

The Fetch API is a modern JavaScript browser API used to make HTTP requests and communicate with servers.

The fetch() method sends a request to a URL and returns a Promise. When the response arrives, JavaScript can read the response body.

Syntax:

fetch("URL")
    .then(response => {
        return response.json();
    })
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });

Explanation:

  • fetch("URL"): Sends an HTTP request.
  • then(): Handles the Promise result.
  • response: Represents the server response.
  • response.json(): Reads and parses JSON response data.
  • data: Contains the parsed response data.
  • catch(): Handles errors in the Promise chain.

Example:

fetch("https://example.com/data")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });

This is a syntax example. The URL must point to a real endpoint that returns JSON for it to work.

8. Understanding async and await

async and await are JavaScript keywords that make asynchronous code easier to read and write.

1. async Keyword

The async keyword is used before a function to make it return a Promise.

Syntax:

async function myFunction() {

    // Asynchronous code

}

2. await Keyword

The await keyword is used inside an async function to wait for a Promise to settle before continuing that function.

Syntax:

const result = await somePromise;

Example:

async function getData() {

    const response = await fetch("/api/data");

    const data = await response.json();

    console.log(data);

}

getData();

Explanation:

  1. async declares an asynchronous function.
  2. fetch() sends a request and returns a Promise.
  3. await waits for the response Promise to settle.
  4. response.json() reads the response body.
  5. The second await waits for the body parsing Promise.
  6. console.log() displays the received data.
Remember:
async = Declares an asynchronous function.
await = Waits for a Promise inside that function. It does not freeze the whole browser interface.

9. Error Handling in AJAX

Errors can occur while sending requests or reading the response from a server. JavaScript should handle these errors so that the user receives proper feedback.

Common Problems:

  • Network connection failure.
  • Server not responding.
  • HTTP error status such as 404 or 500.
  • Invalid JSON response.

Important: response.ok

The response.ok property tells whether the HTTP response status is in the successful range (200 to 299).

Important: fetch() normally does not reject its Promise just because the server returned an HTTP error status such as 404 or 500. We must check response.ok ourselves.

Example:

async function getData() {

    try {

        const response = await fetch("/api/data");

        if (!response.ok) {

            throw new Error("HTTP error: " + response.status);

        }

        const data = await response.json();

        console.log(data);

    } catch (error) {

        console.log("Error:", error);

    }

}

getData();

Explanation:

  • try contains the code that may cause an error.
  • fetch() sends the request.
  • response.ok checks the HTTP status.
  • throw creates an error if the response is not successful.
  • response.json() reads the JSON data.
  • catch handles errors and displays them.
Important:
try...catch can handle network errors, errors we explicitly create for unsuccessful HTTP statuses, and errors while reading or parsing the response.

10. Complete Example: Loading Courses with Fetch

This example demonstrates how a web application can request course information from a server and display it on a page.

HTML:

Course List



Waiting for data...

JavaScript:

async function loadCourses() {

    const status = document.getElementById("status");

    const output = document.getElementById("output");

    status.textContent = "Loading courses...";

    try {

        const response = await fetch("/api/courses");

        if (!response.ok) {

            throw new Error("HTTP error: " + response.status);

        }

        const courses = await response.json();

        output.textContent = courses
            .map(course => course.name)
            .join(", ");

        status.textContent = "Courses loaded.";

    } catch (error) {

        status.textContent =
            "Could not load courses. Check the connection.";

        console.error(error);

    }

}

Explanation:

  1. First, the page displays a waiting message.
  2. The user clicks the Load Courses button.
  3. loadCourses() starts running.
  4. JavaScript displays "Loading courses...".
  5. fetch() sends a request to /api/courses.
  6. The response status is checked using response.ok.
  7. response.json() converts the response body into JavaScript data.
  8. map() extracts the course names.
  9. The course names are displayed on the page.
  10. If an error occurs, catch displays an error message.
Important:
/api/courses is a placeholder endpoint. It must exist on a server and return JSON containing an array of course objects with a name property. This example will not load real courses without a working endpoint.

11. AJAX-Style Update Without a Server

We can also understand the idea of an asynchronous page update using a small local demonstration. This example uses setTimeout() to simulate a delay. It does not send a real HTTP request.

Sample Course Loader

Waiting for a request.

No data loaded yet.

JavaScript Code:

const sampleButton =
document.getElementById("sampleButton");

const sampleStatus =
document.getElementById("sampleStatus");

const sampleOutput =
document.getElementById("sampleOutput");

sampleButton.addEventListener("click", function() {

    sampleStatus.textContent = "Loading...";

    sampleOutput.textContent = "Please wait.";

    setTimeout(function() {

        const course = {
            name: "JavaScript",
            duration: "One Semester"
        };

        sampleOutput.textContent =
            course.name + " - " + course.duration;

});

Explanation:

  • The user clicks the button.
  • The status changes to Loading.
  • setTimeout() waits for 650 milliseconds.
  • A sample JavaScript object is created.
  • The course information is displayed.
  • The status changes to Data loaded.
Remember:
This is only a simulation of an AJAX-style update. It uses hard-coded data and setTimeout(). A real AJAX request communicates with a server.

12. Difference Between Traditional Requests and AJAX

Traditional Web Request

  • A new page or document is commonly loaded.
  • The browser may refresh the entire page.
  • More page content may need to be transferred.

AJAX Request

  • JavaScript sends a request in the background.
  • The response can update only the required page section.
  • The rest of the page stays in place.
  • The page can remain interactive during the request.

13. Advantages of AJAX

  • Reduces unnecessary full-page reloads.
  • Improves the interactive experience.
  • Allows background communication with servers.
  • Can reduce unnecessary data transfer.
  • Updates only the required part of the page.
  • Supports modern web application features.

14. Limitations of AJAX

  • It requires a server or API for real server data.
  • Network failures can prevent requests from completing.
  • Developers must handle errors and loading states.
  • Security must be handled properly on the server.
  • Cross-origin requests may require suitable server permissions.

AJAX is an important web development technique that allows JavaScript to communicate with a server without loading a completely new page.
