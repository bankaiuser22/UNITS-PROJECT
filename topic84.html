XML Schema (XSD)

1. Introduction

XSD stands for XML Schema Definition. It is used to define the structure and rules of an XML document.

XML Schema describes which elements and attributes are allowed in an XML document. It also defines their data types and constraints.

2. Purpose of XML Schema

  • It defines the structure of XML documents.
  • It specifies allowed elements and attributes.
  • It defines data types of elements.
  • It checks the order of child elements.
  • It helps validate XML documents.

3. Features of XSD

  • XSD is written using XML syntax.
  • It supports built-in data types.
  • It supports namespaces.
  • It supports reusable type definitions.
  • It provides detailed constraints.
  • It is more expressive and strongly typed than DTD.

4. Common Data Types in XSD

  • xs:string - Used for text values.
  • xs:decimal - Used for decimal numbers.
  • xs:integer - Used for whole numbers.
  • xs:boolean - Used for true or false values.
  • xs:date - Used for date values.
  • xs:ID - Used for unique identifiers.

5. Important XSD Elements

A. xs:schema

It is the root element of an XML Schema document.

B. xs:element

It declares an element in the XML document.

C. xs:complexType

It defines an element that contains other elements or attributes.

D. xs:sequence

It specifies the order in which child elements must appear.

E. xs:attribute

It declares an attribute for an element.

6. XML Schema Example

Consider a catalog containing products. Each product has a name, price and ID. We can describe this structure using XSD.

catalog.xsd

<?xml version="1.0" encoding="UTF-8"?>

<xs:schema xmlns:xs=
"http://www.w3.org/2001/XMLSchema">

    <xs:element name="catalog">
        <xs:complexType>
            <xs:sequence>

                <xs:element name="product"
                maxOccurs="unbounded">

                    <xs:complexType>
                        <xs:sequence>

                            <xs:element name="name"
                            type="xs:string"/>

                            <xs:element name="price"
                            type="xs:decimal"/>

                        </xs:sequence>

                        <xs:attribute name="id"
                        type="xs:ID"
                        use="required"/>

                    </xs:complexType>

                </xs:element>

            </xs:sequence>
        </xs:complexType>
    </xs:element>

</xs:schema>

7. Explanation of the Example

  • xs:schema defines the XML Schema document.
  • catalog is the root element.
  • xs:complexType defines complex content.
  • xs:sequence specifies the order of elements.
  • product represents each product.
  • maxOccurs="unbounded" allows multiple products.
  • name uses the xs:string data type.
  • price uses the xs:decimal data type.
  • id uses the xs:ID data type.
  • use="required" makes the ID attribute compulsory.

8. Connecting XML with XSD

To validate an XML document using XSD, use the schema location in the XML root element.

XML Header

<?xml version="1.0" encoding="UTF-8"?>

<catalog
xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
xsi:noNamespaceSchemaLocation="catalog.xsd">

    <product id="p101">
        <name>Notebook</name>
        <price>45.50</price>
    </product>

</catalog>

9. Validating XML using XSD

XML documents can be validated using the xmllint utility provided by libxml2.

Command:

xmllint --noout --schema catalog.xsd catalog.xml

If the XML document follows the rules defined in the XSD file, validation succeeds.

10. Advantages of XSD

  • It supports different data types.
  • It provides detailed validation rules.
  • It supports XML namespaces.
  • It defines the order of elements.
  • It is written in XML syntax.

Conclusion

XML Schema (XSD) defines the structure, data types and constraints of an XML document. It provides strong validation and supports namespaces and reusable type definitions.
